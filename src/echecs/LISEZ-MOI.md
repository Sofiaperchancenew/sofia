# Bases d'échecs — copie intégrale

Règle : quand tu donnes une base de données d'échecs, elle est copiée **en entier, au mot près**. Aucun résumé, aucune synthèse, aucune partie jetée.

## Comment donner ta base

1. Dépose ton fichier `.pgn` en pièce jointe du chat (ou dis où il est : `scratch/message-attachments/...`).
2. Donne son nom, sa source et sa licence (ex : « base Lichess 2024, CC0 »).
3. L'agent découpe le fichier en morceaux `morceau-*.json.gz` (500 parties max, ~4 Mo), chaque partie gardée avec son texte PGN complet + ses en-têtes, avec une empreinte SHA-256 par partie et par morceau.
4. Chaque morceau est hébergé (uploads.dev, miroir GitHub), inscrit dans `src/echecs/remote.json`, et la base est inscrite dans `src/echecs/manifest.json` avec son nombre exact de parties.
5. Vérification : le compteur `App.ChessDB` doit afficher exactement le nombre de parties de ton fichier. Si un seul octet manque, ça se voit (SHA-256) et c'est refusé.

Limites : 100 Mo par fichier, ~2 Go au total. Au-delà, on découpe en plusieurs bases nommées (ex : `lichess-2024-a`, `lichess-2024-b`).

Déjà ingérées (octobre 2026, texte intégral vérifié SHA-256) : table ECO française (ton PDF, 53 p. : 2365 lignes, 500 codes A00–E99, morceaux `src/echecs/eco-codes/` + PDF verbatim) ; Kasparov 2128, Fischer 827, Carlsen 7818, Capablanca 597, Nakamura 10220, Morphy 211, Tal 2431, Caruana 6499, Botvinnik 891, Judit Polgar 1825, Alekhine 1661 — plus le socle de 150 annotées — plus TWIC 920 à 1664 au complet (745 numéros, 3 595 925 parties ; total 3 631 183). Les numéros 1 à 919 n'ont aucun fichier sur le site (ni en direct, ni via les anciens chemins, ni via la Wayback) : série complète pour tout ce qui est téléchargeable. Suite éventuelle : reprendre `src/echecs/twic-runner.js` (bornes FROM/TO en tête), numeros suivis dans `manifest.json`.

## Sources évaluées (octobre 2026)

- chess.ceo : station d'analyse gratuite (Stockfish, opening explorer, DB, PGN, fiches /player en React) — appli web uniquement, aucun téléchargement en bloc, page /player vide sans JS.
- ajedrezdata.com OTB : vraies bases PGN gratuites (AJ-OTB-000 = 4 471 785 parties jusqu'en avril 2023, AJ-OTB-001 = 868 015 parties jusqu'en août 2024) mais liens via raccourcisseur l--l.top injoignable d'ici + plusieurs Go — non ingérable dans ces quotas.
- chesstempo.com : 5M+ parties mais appli web uniquement, aucun téléchargement en bloc. Pris le 2026-10-07 : `openingNames` incrusté dans la page `game-database/chess-openings/` → `src/echecs/chesstempo-openings.json` (2963 variantes nommées + FEN + nb coups, 421 Ko, usage personnel) ; les parties elles-mêmes restent non téléchargeables.
- lumbrasgigabase.com (Lumbra's Gigabase, Michael Jansen, CC BY-NC-SA 4.0, usage personnel) : base gratuite SCID/PGN dédupliquée (OTB + Online, mensuelles). Table ECO (10360 lignes coups→code A00–E99, page eco-codes-en) prise le 2026-10-07 → `src/echecs/lumbras-eco.json` (1,23 Mo). Les PGN eux-mêmes sont hébergés sur MEGA (clés non exposées, non téléchargeables d'ici) : pour ingérer des parties, télécharge le 7z voulu et dépose-le en pièce jointe (workflow classique ci-dessus).
- cipherchess.com/mega-database : 10M+ parties 1475–2026, recherche par position/joueur/ouverture + répertoire, mais appli Next.js sur compte (« Try Free », /signup), aucun dump public, aucun endpoint public (chunk = loader, /api/games → 404). Rien à prendre d'ici ; GameKnot couvre déjà le livre live.
- chessgames.com : aucun téléchargement en bloc (consultation page par page uniquement).
- gameknot.com/chess-games-database.pl : 4 046 380 parties en ligne 1600+ depuis 2000 + 1 673 750 OTB 2000+, explorateur par position SANS compte ni clé : `GET /chess-games-database.pl?rv=1&h=0|1&nid=0&f=FEN` → texte `cgd.1.0` (coups + elo moy + blancs/nulles/noirs). Pris le 2026-10-07 comme livre live (`App.GkBook`, via superFetch) : pas de dump à ingérer, c'est du direct.
- database.chessbase.com : 8M parties derrière comptes/offre payante, aucun dump public (page = coquille React vide sans JS) ; shop.chessbase.com/en/openings/tree = boutique, produit/arborescence payante à acheter, pas un PGN libre.
- chessify (9M) : accès en ligne sur compte + abonnement, aucun téléchargement (page /analysis = shell React vide sans JS, même conclusion).
- lichess.org (requêtes à distance, sans clé) : explorateur `explorer.lichess.ovh/masters|lichess?fen=` = 401 Cloudflare partout (navigateur + proxy, 2026-10-07) — mort pour l'instant ; EN REVANCHE `lichess.org/api/cloud-eval?fen=&multiPv=` = 200 direct, analyse Stockfish profonde (test : après 1.e4, e5 +0.22→-0.22 blanc, c6, c5, prof 60, 119k nœuds). - database.chessmont.com (Chessmont Open Database, Astro statique) : 16 fichiers listés (final 21,5M parties + 1,8Md index + 1,35Md FEN, pools Chess.com/Lichess 2400+/2500+, FEN, externes, openings.tsv) MAIS tous les « View » pointent vers Kaggle (compte requis) ; aucun miroir Hugging Face (API search vide). - Elite Chess Database (app iOS) : application seule, aucune donnée exportable.
- scid-v5.2.202603_windows_x64.zip (pièce jointe utilisateur) : le LOGICIEL SCID 5.2 Windows (scid.exe + Tcl + Stockfish + 2 NNUE, 1006 entrées, ~82 Mo) — inexécutable dans un navigateur, MAIS il embarque 4 livres d'ouvertures Polyglot (format 16 octets/entrée : clé u64 BE, coup u16, poids u16, learn u32, trié par clé) + scid.eco (lignes `CODE "nom" suite-SAN *`, ex. `A00b "Barnes Opening" 1.f3 *` ; scid_fr.eco = 263 Ko). Rétro-ingénierie complète et VÉRIFIÉE : clé Zobrist Polyglot = table officielle 781 constantes (python-chess), index pièce = (type-1)*2 + couleur (BLANC=1, NOIR=0 — chess.WHITE vaut True !), cases a1=0, roques 768-771 (K,Q,k,q), prise-en-passant 772+colonne (si pion adverse à portée), trait blanc 780 ; coup : départ=(m>>6)&63, arrivée=m&63, promo=(m>>12)&7 (1=N,2=B,3=R,4=Q) ; clé initiale prouvée 0x463B96181691FC9C (chaîne e4→{e5,c5}→Nf3→{Nc6,a6} cohérente). PRIS le 2026-10-07 : `src/echecs/scid-performance.bin` (1 487 264 o, 92 954 positions, copie intégrale du .bin + table dans index.html, exception binaire à la règle des morceaux — pas du PGN) + `App.ScidBook` (hash FEN→clé, recherche dichotomique, choix pondérés, `pick()` pour usage moteur futur) + 2 hooks + persona. Racine vérifiée : e4/d4/c4 puis e5/c5. NON PRIS : Elo2400.bin (155 878 entrées mais racine sabotée — e3/a3/c3/d3 seulement, pas de e5/c5 après e4 : livre anti-théorie, DANGEREUX comme livre principal), gm2600.bin (21 671, racine c3), varied.bin (92 229, poids plats x1 partout), scid.eco (noms OK mais conversion SAN→FEN = chantier ; LumbrasEco + ChessTempo couvrent déjà).
